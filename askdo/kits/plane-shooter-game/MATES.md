# Plane Shooter Game Mates

## Crew

Source: `ROLES.json`

Name: Browser Game Delivery Crew

Purpose: Create, verify, and package a small standalone browser game for a user ask.

## Role Contract

Source: `ROLES.json`

Roles are stable responsibility seats. Shared roles use archetypes and scenario bindings so browser arcade, puzzle, or action game scenarios can adapt the same role patterns without duplicating role definitions.

## Mate Roster

Source: `ROSTER.json`

Mates are concrete workers assigned to roles. Add, remove, pause, or replace mates in `ROSTER.json`; update this Markdown only when the operating contract changes.

## Assignment Notes

- Assignments are created per run.
- Each assignment must be owned by one active mate from `ROSTER.json`.
- A mate may receive multiple assignments only when they fit its responsibility.
- Permission expansion or boundary ambiguity must be escalated before execution.

## Change Rules

- Role changes go in `ROLES.json`.
- Employee or mate changes go in `ROSTER.json`.
- Flow routing changes go in `FLOW.md`.
- Execution entry changes go in `ENTRY.md`.
- This file summarizes the operating contract and should not become the roster database.
