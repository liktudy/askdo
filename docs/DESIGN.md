# Askdo Design

Version: 0.1

Owner: Askdo product and system design

Status: initial product scaffold

## Goal

Askdo turns a user ask into a reusable business capability and an executable multi-agent flow.

```text
ask -> build -> flow -> run -> result -> level
```

The user should not need to understand organization architecture. Askdo hides the internal governance model behind simple product terms.

## Audience

- product designers
- implementation engineers
- AI agent integrators
- future auditors

## Product Shape

Askdo is:

- an installable capability layer
- a plugin-first agent behavior pack
- a kit builder and runner
- a user-owned asset manager
- a disciplined execution loop

Askdo is not:

- a heavy multi-agent runtime
- a heavy MCP service
- a web dashboard
- a GitHub app
- a low-code flow editor in the initial phase

## Architecture

```text
Host Agent Tool
  -> Askdo brain
    -> build or reuse kit
      -> run flow
        -> produce result
          -> record level signal
```

Host tools may include Codex, Claude Code, Cursor, OpenCode, or other agent tools.

## Source Of Truth

Askdo source of truth:

- `AGENTS.md`
- `docs/`
- `brain/rules/`
- `brain/schemas/`
- `brain/flows/`
- `skills/`
- `templates/`
- `platforms/`
- `kits/*/kit.json`
- `kits/*/FLOW.md`
- `kits/*/MATES.md`

Adapters and runtime output are not source of truth.

## Execution Model

Askdo uses a hybrid model:

- linear main flow
- local parallel mate work when useful
- central routing by the brain
- review loops when quality or boundary risk requires them

## Boundary

Simple user experience must not weaken internal control.

Askdo must preserve:

- final user authority
- approvals for high-risk operations
- permission boundaries
- reusable assets
- lifecycle state
- performance feedback
- traceable decisions
